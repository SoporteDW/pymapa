Seguimos con CM-02 · Diseñar y ajustar propuestas de valor, segunda capacidad del dominio CM · Cliente, mercado y creación de valor.
Aquí la trampa conceptual principal es reducir “propuesta de valor” a un mensaje comercial o a una descripción de producto. Para Pymapa, eso sería insuficiente.
La pregunta irreducible será:
¿Puede la organización traducir una comprensión suficientemente válida del cliente en una propuesta de valor clara, pertinente y diferenciada, y ajustarla con evidencia sobre lo que realmente se entrega, percibe y valora?
La cadena nuclear será:
Customer Need → Value Hypothesis → Value Proposition → Offer/Experience → Evidence → Perceived Value → Delivered Value → Adjustment
Y fijamos desde el comienzo:
NEED ≠ VALUE PROPOSITION ≠ OFFER ≠ PRODUCT ≠ PRICE ≠ VALUE PERCEPTION ≠ VALUE REALIZED

# 2. Identidad
## Definición productiva V1
CM-02 evalúa la capacidad de la organización para formular, contrastar y ajustar propuestas de valor que conecten de manera suficientemente clara y creíble necesidades materiales de segmentos o actores relevantes con beneficios, resultados o experiencias que la organización puede entregar de forma diferenciada y sostenible.
La capacidad no evalúa solo:
“qué dice la empresa”.
Evalúa la correspondencia entre:
lo que el cliente necesita → lo que la empresa promete → lo que realmente ofrece → lo que el cliente percibe → lo que finalmente obtiene.
# 3. Unidad de análisis
Definimos:
### VALUE PROPOSITION CASE — VPC
Caso en el que una población o segmento material recibe una promesa de valor destinada a resolver, mejorar o evitar una condición relevante mediante una oferta o experiencia concreta.
La estructura mínima:
SEGMENT/ACTOR + NEED + PROMISED VALUE + OFFER + EVIDENCE
Esto permite tener varias propuestas de valor dentro de una misma empresa.
# 4. Propuesta de valor ≠ slogan
Ejemplo:
“Soluciones digitales para hacer crecer tu negocio.”
Eso puede ser un mensaje.
No necesariamente una propuesta de valor suficientemente diagnóstica.
Para Pymapa, una propuesta de valor debe permitir entender al menos:
- para quién;
- qué necesidad relevante atiende;
- qué resultado o beneficio promete;
- mediante qué oferta/capacidad;
- por qué resulta suficientemente creíble o diferenciada.
### P-CM02-CORE-01
Mensaje comercial y propuesta de valor no son objetos equivalentes.
# 5. Propuesta de valor ≠ producto
Un mismo producto puede sostener propuestas de valor distintas para diferentes segmentos.
Y distintas ofertas pueden sostener una misma propuesta.
Por tanto:
### P-CM02-01
Producto/servicio es un mecanismo de entrega de valor; no debe confundirse automáticamente con la propuesta de valor.
# 6. Propuesta de valor ≠ precio
El precio afecta percepción de valor y decisión de compra, pero no define por sí solo la propuesta.
Una empresa puede competir por:
- velocidad;
- conveniencia;
- riesgo reducido;
- expertise;
- personalización;
- disponibilidad;
- experiencia;
- desempeño;
- resultado;
- costo total;
- confianza.
### P-CM02-02
Precio es un componente potencial de la ecuación de valor, no la propuesta de valor completa.
# 7. Aplicabilidad
No toda empresa necesita múltiples propuestas de valor.
### APP-CM02-01
La necesidad de diferenciar propuestas de valor aumenta únicamente cuando segmentos o contextos materialmente distintos requieren promesas, beneficios, condiciones o mecanismos de entrega diferentes.
Si una empresa atiende una población relativamente homogénea, una única propuesta puede ser suficiente.
# 8. Materialidad
Una VPC se vuelve material cuando puede cambiar:
- adquisición;
- conversión;
- pricing;
- producto;
- servicio;
- retención;
- posicionamiento;
- inversión;
- segmento prioritario;
- canal;
- crecimiento;
- rentabilidad.
# 9. Fronteras
## CM-02 vs CM-01
CM-01 responde:
¿qué necesita o valora el cliente?
CM-02 responde:
¿cómo convertimos esa comprensión en una promesa de valor suficientemente pertinente?
Por tanto:
buena comprensión no garantiza buena propuesta.
# 10. CM-02 vs CM-03
CM-02 define:
qué valor ofrecemos y por qué debería importar.
CM-03 evalúa:
cómo captamos, convertimos y desarrollamos la relación comercial.
Una propuesta excelente puede estar mal comercializada.
# 11. CM-02 vs CM-05
CM-02 puede prometer:
“respuesta en menos de 2 horas”.
CM-05 deberá evaluar si la experiencia y el servicio sostienen esa promesa.
Por tanto:
promesa ≠ entrega.
# 12. CM-02 vs CM-06
CM-06 evaluará:
si el valor creado puede medirse y gestionarse.
CM-02 evalúa:
la arquitectura de la propuesta y su correspondencia con necesidad, oferta y evidencia.
# 13. CM-02 vs OP
Si la propuesta promete:
personalización rápida,
pero el proceso no puede entregarla:
CM-02 puede detectar:
promesa insuficientemente creíble o sostenible.
OP puede detectar:
capacidad operativa insuficiente.
Misma realidad, diagnósticos distintos.
# 14. Modelo necesidad–valor–propuesta
Necesitamos separar siete objetos.
### CUSTOMER NEED
Condición que importa al cliente.
### VALUE HYPOTHESIS
Hipótesis sobre qué beneficio/respuesta sería valioso.
### VALUE PROPOSITION
Promesa estructurada de valor para una población.
### OFFER
Conjunto concreto de producto, servicio, condiciones y experiencia mediante el que se intenta entregar.
### EXPECTED VALUE
Valor que el cliente espera recibir.
### PERCEIVED VALUE
Valor que cree recibir.
### REALIZED VALUE
Resultado/beneficio efectivamente obtenido.
Por tanto:
HYPOTHESIS ≠ PROPOSITION ≠ OFFER ≠ EXPECTATION ≠ PERCEPTION ≠ REALIZED VALUE
# 15. Value hypothesis
Antes de una propuesta validada puede existir:
“creemos que estas empresas valorarán X porque Y”.
Eso es legítimo.
Definimos:
### VALUE HYPOTHESIS — VH
Suposición explícita sobre qué resultado, beneficio o reducción de fricción tendrá suficiente valor para una población determinada.
### P-CM02-03
Una Value Hypothesis debe permanecer como hipótesis hasta disponer de evidencia suficiente sobre su relevancia y entrega.
# 16. Estructura mínima de propuesta de valor
Proponemos:
### VP-PYM
Para [segmento/actor], que necesita [resultado/problema/contexto], ofrecemos [beneficio/resultado] mediante [oferta/capacidad], de una forma suficientemente diferenciada por [razón relevante].
No es una plantilla obligatoria de copywriting.
Es una estructura interna de razonamiento.
# 17. Beneficio ≠ característica
Ejemplo:
Característica:
“dashboard en tiempo real”.
Beneficio:
“visibilidad suficiente para decidir inventario antes de perder ventas”.
### P-CM02-04
Características de oferta no deben confundirse automáticamente con beneficios o resultados para el cliente.
# 18. Beneficio ≠ resultado comprobado
Una empresa puede prometer:
“reduce errores”.
Eso es una claim.
Hasta que exista evidencia suficiente:
no debemos tratarlo como valor realizado.
Definimos:
### VALUE CLAIM
afirmación sobre un beneficio esperado o entregable.
Puede tener distintos niveles de evidencia.
# 19. Diferenciación
Diferenciar no significa:
ser único en todo.
Definimos:
### RELEVANT DIFFERENTIATION
diferencia suficientemente importante para el cliente y suficientemente vinculada con la elección o preferencia frente a alternativas relevantes.
Las alternativas pueden ser:
- competidor;
- solución interna;
- no hacer nada;
- workaround;
- producto sustituto;
- proceso manual.
### P-CM02-05
La diferenciación debe evaluarse respecto de alternativas reales del cliente, no únicamente competidores directos.
# 20. Diferenciación irrelevante
Ejemplo:
“tenemos 47 funcionalidades”.
Si el cliente valora solo:
implementación sencilla y soporte confiable,
esas funcionalidades no necesariamente diferencian positivamente.
### P-CM02-06
Una diferencia solo aporta valor cuando modifica suficientemente percepción, elección, resultado o experiencia para el segmento aplicable.
# 21. Uniqueness ≠ defensibility
Algo puede ser único temporalmente y fácil de copiar.
Pero CM-02 no necesita exigir “moat” a todas las pymes.
Podemos distinguir:
### DISTINCTIVENESS
El cliente percibe una diferencia relevante.
### DEFENSIBILITY
La empresa puede sostenerla suficientemente.
La segunda importa cuando la propuesta depende materialmente de ello.
# 22. Promesa y credibilidad
Una propuesta puede ser atractiva pero poco creíble.
La credibilidad puede provenir de:
- evidencia;
- demostración;
- prueba;
- reputación;
- experiencia;
- referencia;
- garantía;
- capacidad observable;
- diseño de oferta.
### P-CM02-07
Atractividad de una promesa y credibilidad de esa promesa deben mantenerse como dimensiones distintas.
# 23. Claim strength
Una afirmación:
“somos los mejores”
requiere evidencia distinta de:
“respondemos normalmente en menos de dos horas”.
Definimos:
### CLAIM SUPPORT
grado en que una afirmación material cuenta con evidencia suficiente para el contexto en el que se utiliza.
No hacemos revisión legal de publicidad como capacidad general, pero evitamos:
claim sin soporte.
# 24. Oferta
La oferta puede incluir:
- producto;
- servicio;
- bundle;
- alcance;
- nivel de servicio;
- implementación;
- garantía;
- soporte;
- condiciones;
- modalidad;
- precio;
- riesgo asumido;
- experiencia.
Por tanto:
value proposition puede mantenerse mientras la oferta cambia.
# 25. Oferta ≠ valor
Agregar:
más funcionalidades, más soporte, más personalización
puede aumentar costo sin aumentar valor percibido.
### P-CM02-08
Más oferta no implica automáticamente más valor.
# 26. Precio
En CM-02 lo tratamos solo como parte de:
value exchange.
No hacemos todavía un modelo completo de pricing.
Necesitamos observar:
### PRICE/CONDITION FIT
si precio y condiciones son compatibles con el valor esperado/percibido dentro de la propuesta.
Pero:
precio bajo ≠ alta propuesta de valor.
# 27. Willingness to pay
Debe tratarse cuidadosamente.
Lo que alguien dice que pagaría:
no equivale automáticamente a comportamiento real de compra.
### P-CM02-09
Willingness-to-pay declarada y conducta de compra deben conservarse como evidencias distintas.
# 28. Promesa ≠ entrega
Ésta será una distinción estructural.
### PROMISED VALUE
Lo que decimos que ocurrirá.
### DELIVERED VALUE
Lo que la oferta efectivamente entrega.
### PERCEIVED VALUE
Cómo el cliente lo interpreta.
### REALIZED VALUE
Resultado que finalmente obtiene.
Puede existir:
delivered value suficiente,
pero:
perceived value bajo.
O:
perceived value alto,
pero:
realized value insuficiente a largo plazo.
# 29. Ajuste de propuesta
Ajustar no significa necesariamente:
cambiar producto.
Puede cambiar:
- segmento;
- problema priorizado;
- promesa;
- mensaje;
- bundle;
- condiciones;
- prueba;
- onboarding;
- precio;
- alcance;
- diferenciador.
### P-CM02-10
La propuesta de valor puede ajustarse sin modificar necesariamente el producto central.
# 30. Evidence-to-Value
Necesitamos varios tipos de evidencia:
### E-VP-01 · CUSTOMER EVIDENCE
Qué valora/necesita el cliente.
### E-VP-02 · CHOICE EVIDENCE
Qué elige o descarta.
### E-VP-03 · USAGE EVIDENCE
Cómo utiliza la oferta.
### E-VP-04 · PAYMENT EVIDENCE
Qué acepta pagar/renovar.
### E-VP-05 · OUTCOME EVIDENCE
Qué resultado obtiene.
### E-VP-06 · EXPERIENCE EVIDENCE
Cómo percibe la experiencia.
### E-VP-07 · COMPETITIVE/ALTERNATIVE EVIDENCE
Cómo se compara con alternativas.
No toda VPC necesita todas.
# 31. Fit ≠ proof
Una propuesta puede ser:
conceptualmente coherente con CM-01
pero todavía no tener evidencia suficiente de mercado.
Definimos:
### VALUE PROPOSITION FIT
grado en que necesidad, promesa, oferta, evidencia y diferenciación mantienen correspondencia suficiente para el segmento y uso aplicables.

# 33. Information Needs
Resultan 22 NI.
La pregunta núcleo será:
¿Para quién es esta propuesta, qué necesidad material pretende resolver, qué valor promete, mediante qué oferta, frente a qué alternativa, con qué evidencia y qué diferencia existe entre lo prometido, percibido y realmente obtenido?
# 34. Captura P1
Preguntas simples:
“¿Por qué sus mejores clientes los eligen?”
“¿Qué problema concreto esperan resolver cuando los contratan?”
“¿Qué prometen ustedes que ocurrirá?”
“¿Qué alternativa usaría el cliente si ustedes no existieran?”
“¿Qué parte de su oferta valora realmente y cuál usa poco?”
“¿Dónde prometen algo que después cuesta mucho entregar?”
# 35. P2 · Triggers
Profundizamos ante:
- mensaje genérico;
- “calidad y servicio” como única diferenciación;
- muchas features;
- bajo cierre pese a interés;
- precio constantemente cuestionado;
- descuentos frecuentes;
- producto infrautilizado;
- churn tras onboarding;
- expectativa vs entrega;
- segmentación diferente pero misma propuesta;
- claims sin evidencia;
- propuesta histórica;
- cliente compra por motivo diferente al que empresa cree;
- alta satisfacción pero baja renovación;
- alta conversión con baja rentabilidad.

# 37. Contradicciones
### CONTR-CM02-01
PROMISED_VALUE_vs_CUSTOMER_NEED
Promesa atractiva pero no conectada con necesidad evidenciada.
### CONTR-CM02-02
CLAIM_vs_DELIVERY
Se promete una condición que la operación no sostiene.
### CONTR-CM02-03
PERCEIVED_VALUE_vs_REALIZED_VALUE
Cliente siente valor inicial, pero resultado posterior es débil.
### CONTR-CM02-04
COMPANY_DIFFERENTIATION_vs_CUSTOMER_CHOICE
Empresa cree diferenciarse por A, clientes eligen por B.
### CONTR-CM02-05
FEATURE_RICHNESS_vs_LOW_USAGE
Muchas funcionalidades con bajo uso/valor.
# 38. Evidencia y suficiencia
### SUFF-CM02-01
CM-02 alcanza suficiencia cuando cada propuesta material tiene segmento y necesidad suficientemente evidenciados, una promesa clara y creíble, una oferta capaz de sostenerla y evidencia proporcional sobre relevancia, percepción y entrega suficiente para la decisión de mantenerla o ajustarla.
No exige:
demostrar causalmente todo el valor económico.
# 39. Confianza
Distinguimos:
### NEED CONFIDENCE
Viene en gran medida de CM-01.
### VALUE HYPOTHESIS CONFIDENCE
Qué tan sustentado está que determinado beneficio importa.
### PROPOSITION CONFIDENCE
Qué tan sustentada está la propuesta integrada.
### DELIVERY CONFIDENCE
Qué tan probable/observado es que la empresa pueda entregarla.
### REALIZED VALUE CONFIDENCE
Qué evidencia existe del resultado para el cliente.
### CAND-MOTOR-CM02-01
La confianza en una necesidad evidenciada no debe transferirse automáticamente a la hipótesis de valor, la oferta o el valor realizado.

# 42. Guardrails
- No exigir Value Proposition Canvas.
- No exigir slogan.
- No confundir slogan con propuesta.
- No confundir producto con propuesta.
- No confundir feature con beneficio.
- No confundir beneficio con resultado realizado.
- No asumir precio bajo = valor.
- No asumir precio alto = diferenciación.
- No exigir unicidad absoluta.
- No definir competencia solo como competidor directo.
- No asumir más features = más valor.
- No asumir personalización = más valor.
- No asumir innovación = valor.
- No asumir necesidad evidenciada = propuesta evidenciada.
- No asumir intención de compra = compra.
- No asumir willingness-to-pay declarada = pago real.
- No confundir satisfacción con valor realizado.
- No inferir causalidad de valor desde resultado comercial aislado.
- No exigir múltiples propuestas sin materialidad.
- No exigir una propuesta diferente por cada segmento descriptivo.
- No considerar claim comercial como hecho.
- No exigir pruebas cuantitativas para toda propuesta.
- No descartar evidencia cualitativa.
- No confundir percepción y realización de valor.
- No confundir entrega y percepción.
- No asumir que baja conversión implica mala propuesta.
- No asumir que alta conversión implica buena propuesta.
- No ignorar sostenibilidad operativa de la promesa.
- No ignorar alternativas no tecnológicas/no comerciales.
- No mantener propuesta por sunk cost.
- No obligar a modificar producto cuando basta modificar oferta/promesa.
- No asumir que una propuesta histórica sigue vigente.
- No convertir lenguaje generado por IA en evidencia de relevancia.
# 43. Candidatos para el Motor
### CAND-MOTOR-CM02-02
Value Proposition Case debe asociar Segment/Actor + Need + Value Hypothesis + Proposition + Offer + Evidence.
### CAND-MOTOR-CM02-03
Value Hypothesis debe permanecer separada de validated proposition.
### CAND-MOTOR-CM02-04
Product, Offer y Value Proposition deben modelarse como objetos distintos.
### CAND-MOTOR-CM02-05
Promised, Expected, Perceived, Delivered y Realized Value deben poder coexistir como estados diferentes.
### CAND-MOTOR-CM02-06
Alternative puede ser competitor, internal solution, workaround o no-action.
### CAND-MOTOR-CM02-07
Differentiation debe requerir relevancia para el cliente y no solo diferencia descriptiva.
### CAND-MOTOR-CM02-08
Claims materiales deben poder asociarse a evidencia y confidence independientes.
### CAND-MOTOR-CM02-09
Offer complexity puede producir un finding negativo incluso si aumenta funcionalidad.
### CAND-MOTOR-CM02-10
La propuesta debe poder ajustarse conservando trazabilidad de hipótesis, evidencia y versión anterior.
### CAND-MOTOR-CM02-11
Gaps entre promised/delivered/perceived/realized value deben poder activar capacidades diferentes y no una causa automática única.
# 44. IA y propuesta de valor
Dos controles importantes:
### CAND-MOTOR-AI-CM02-01
Una propuesta de valor redactada por IA sigue siendo una hipótesis de diseño hasta que su pertinencia esté sustentada por evidencia de cliente y capacidad de entrega.
### CAND-MOTOR-AI-CM02-02
La IA puede generar alternativas de propuesta u oferta, pero no debe convertir plausibilidad lingüística en evidencia de diferenciación o valor.

La arquitectura queda:
Customer/Segment → Need → Value Hypothesis → Promise → Alternative/Differentiation → Offer → Evidence → Expected/Perceived/Delivered/Realized Value → Adjustment.
Y dejamos fijadas siete separaciones esenciales:
NEED ≠ VALUE HYPOTHESIS
VALUE HYPOTHESIS ≠ VALUE PROPOSITION
VALUE PROPOSITION ≠ PRODUCT
PRODUCT ≠ OFFER
FEATURE ≠ BENEFIT
PROMISED VALUE ≠ DELIVERED VALUE
DELIVERED VALUE ≠ REALIZED VALUE
La regla central de CM-02 queda:
Pymapa no evaluará la calidad de una propuesta de valor por lo atractiva que suena ni por la cantidad de funcionalidades que contiene. Evaluará si conecta una necesidad suficientemente evidenciada con una promesa clara, creíble y diferenciada, respaldada por una oferta capaz de entregarla y por evidencia proporcional sobre aquello que el cliente realmente percibe y obtiene.

## El finding debe preservar el VPC
Evitemos:
“La propuesta de valor es débil.”
Preferimos:
“Para microempresas de comercio electrónico que buscan reducir tiempo operativo, la propuesta enfatiza amplitud funcional, pero la evidencia disponible indica que los clientes priorizan simplicidad y velocidad de implementación, generando una diferencia material entre el beneficio prometido y el criterio de elección observado.”
Tenemos:
SEGMENT + NEED + PROPOSITION + EVIDENCE + MISMATCH
### FIND-CM02-01
Todo finding CM-02 debe conservar el Value Proposition Case que originó la evaluación.

# Fit Gap ≠ Delivery Gap
Supongamos:
el cliente valora la promesa, pero la empresa no logra entregarla consistentemente.
Eso no significa:
“mala propuesta”.
Puede existir:
PROPOSITION FIT positivo + DELIVERY GAP operativo.
Otro caso:
la empresa entrega perfectamente algo que el cliente ya no valora.
Entonces:
DELIVERY positivo + PROPOSITION RELEVANCE GAP.
### CAND-MOTOR-CM02-12
Relevance fit y delivery fit deben permanecer como estados diferentes.

# Vocabulario de decisión
CM-02 necesita 14 direcciones posibles.
### CLARIFY
Aclarar segmento, necesidad o promesa.
### REFRAME
Cambiar la manera en que se formula el valor.
### REFINE
Ajustar beneficio, alcance o detalle.
### DIFFERENTIATE
Fortalecer una diferencia materialmente relevante.
### SIMPLIFY
Reducir oferta o complejidad innecesaria.
### REBUNDLE
Cambiar combinación de producto/servicio/condiciones.
### REPRICE
Ajustar precio/condiciones cuando el value exchange lo justifica.
### SUPPORT_CLAIM
Fortalecer evidencia o prueba.
### ALIGN_DELIVERY
Corregir correspondencia entre promesa y capacidad real.
### TEST
Contrastar hipótesis de valor.
### RETARGET
Cambiar segmento o población.
### MAINTAIN
Mantener propuesta actual.
### RETIRE
Retirar una propuesta que dejó de ser pertinente.
### NO_ACTION
No intervenir cuando la suficiencia ya es adecuada.

# No toda baja conversión implica cambiar propuesta
Una baja conversión puede provenir de:
- targeting;
- canal;
- proceso comercial;
- fricción;
- confianza;
- precio;
- timing;
- experiencia;
- seguimiento.
### P-CM02-11
El desempeño comercial no debe atribuirse automáticamente a la calidad de la propuesta de valor sin discriminación causal suficiente.
Esto prepara la frontera con CM-03.

# Minimum Sufficient Value Proposition
Formalizamos:
### INT-CM02-01
La propuesta de valor debe contener la mínima complejidad necesaria para comunicar y sostener una promesa materialmente relevante, creíble y diferenciada para el segmento aplicable.
Más beneficios, más features y más mensajes:
no siempre mejoran la propuesta.

# Testing de propuesta
Cuando existe incertidumbre suficiente, podemos experimentar.
Pero la prueba debe responder algo específico:
- ¿el problema importa?
- ¿el beneficio atrae?
- ¿la diferencia cambia elección?
- ¿el precio parece compatible?
- ¿la promesa es creíble?
- ¿la oferta se comprende?
- ¿el cliente obtiene realmente el resultado?
### VALUE PROPOSITION EXPERIMENT — VPE
Prueba delimitada destinada a reducir una incertidumbre material dentro de un VPC.

# Experimento ≠ validación total
Ejemplo:
Una landing page con alta respuesta puede evidenciar:
interés en una promesa.
No necesariamente:
willingness-to-pay estable, delivery fit o realized value.
### P-CM02-12
La evidencia de una prueba debe conservar el alcance exacto de lo que demuestra.

# Validación
CM-02 necesita V0–V4.
### V0 · UNKNOWN
No existe suficiente definición/evidencia.
### V1 · VALUE-HYPOTHESIS
Existe una hipótesis de valor explícita.
### V2 · PROPOSITION-EVIDENCED
Existe evidencia suficiente de relevancia inicial de necesidad, promesa o diferenciación.
### V3 · PROPOSITION-FIT
Propuesta, oferta y evidencia mantienen correspondencia suficiente para el segmento aplicable.
### V4 · VALUE-FIT-SUSTAINED
La propuesta mantiene suficiente pertinencia y correspondencia con percepción/entrega/valor a través del tiempo o uso recurrente.
No toda VPC necesita V4.

# Un punto importante: V2 puede ser suficiente temporalmente
En una oferta nueva puede ser legítimo operar con:
V2 · PROPOSITION-EVIDENCED
mientras se acumula evidencia de delivery y realized value.
Lo que no debemos hacer es presentar:
V2 como V4.
### CAND-MOTOR-CM02-13
El nivel de validación requerido debe depender del compromiso y madurez del VPC; una propuesta nueva puede operar legítimamente con evidencia parcial si la incertidumbre permanece explícita.

# Value attribution
Si un cliente mejora un resultado después de utilizar la oferta, no atribuimos automáticamente:
todo el resultado a la propuesta.
Reutilizamos:
ATTR-0:3.

# 14. Contextualización, Knowledge Governance y cierre
## Proporcionalidad SME
Una microempresa puede tener una propuesta de valor fuerte sin:
- brand book;
- product marketing team;
- research department;
- sofisticado pricing model.
Puede bastar con:
segmento claro + necesidad real + oferta simple + promesa verificable + evidencia consistente.
Una pyme con varias líneas de negocio puede necesitar múltiples VPC.

# B2B
En B2B puede ser necesario distinguir:
- valor para organización;
- valor para buyer;
- valor para usuario;
- valor para decisor.
Una misma oferta puede generar:
beneficios diferentes por actor.
Esto conecta con CM-01.
### P-CM02-13
Cuando múltiples actores intervienen materialmente, una propuesta puede necesitar expresar distintas dimensiones de valor sin perder coherencia de la oferta global.

# Propuesta institucional vs VPC
Una empresa puede tener un posicionamiento general.
Pero Pymapa debe poder manejar múltiples:
Value Proposition Cases
debajo de esa promesa institucional.
Así no confundimos:
marca corporativa
con:
propuesta funcional por segmento/caso.

# IA
Una IA puede ayudar a:
- generar alternativas;
- reescribir mensajes;
- comparar claims;
- sintetizar feedback.
Pero no cambia la arquitectura de evidencia.
### CAND-MOTOR-AI-CM02-03
La optimización lingüística de una propuesta mediante IA no constituye evidencia de relevancia, diferenciación ni realized value.
### CAND-MOTOR-AI-CM02-04
Las propuestas generadas o modificadas mediante IA deben conservar trazabilidad de la hipótesis y evidencia que justifican su contenido material.

# Source lifecycle y grounding
CM-02 puede fundamentarse externamente con literatura sólida sobre customer value, marketing, diseño de oferta e innovación, pero los objetos que estamos creando son arquitectura propia Pymapa.
Para esta capacidad no necesitamos inflar bibliografía simplemente para aparentar rigor.
La regla aprobada sigue siendo:
incorporar fundamentación externa cuando fortalezca una decisión conceptual, frontera o definición; no convertir el Knowledge Master en una colección indiscriminada de fuentes.
