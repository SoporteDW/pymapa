Seguimos con CM-06 · Medir y gestionar creación de valor, sexta y última capacidad del dominio CM · Cliente, mercado y creación de valor.
Esta capacidad es especialmente importante porque cierra todo el dominio y conecta muchas de las anteriores. Aquí debemos impedir que Pymapa llame “valor” a cualquier resultado positivo, ingreso o KPI.
La pregunta irreducible será:
¿Puede la organización identificar qué valor espera crear para clientes y negocio, medir suficientemente si ese valor se produce y utilizar esa evidencia para decidir dónde sostener, mejorar, reducir o dejar de invertir?
La cadena nuclear será:
Value Intent → Value Recipient → Expected Outcome → Evidence/Metric → Observed Outcome → Attribution → Value Created → Value Captured → Trade-off → Management Decision → Learning
Y fijamos desde el inicio:
REVENUE ≠ VALUE CREATED
CUSTOMER VALUE ≠ BUSINESS VALUE
VALUE CREATED ≠ VALUE CAPTURED
OUTPUT ≠ OUTCOME ≠ IMPACT
MEASUREMENT ≠ ATTRIBUTION

# 1. Identidad
## Definición productiva V1
CM-06 evalúa la capacidad de la organización para definir los resultados de valor materialmente relevantes para clientes y negocio, producir evidencia suficiente sobre su generación, distinguir creación de valor de captura económica y utilizar esa evidencia para gestionar decisiones, trade-offs y sostenibilidad del modelo.
La capacidad no pregunta solo:
“¿cuánto vende la empresa?”
Pregunta:
¿qué valor se genera, para quién, cómo lo sabemos, cuánto logra capturar la empresa y qué decisiones deben modificarse a partir de esa evidencia?
# 2. Unidad de análisis
Definimos:
### VALUE CREATION CASE — VCC
Caso en el que una actividad, oferta, relación, intervención o capacidad pretende producir un resultado material de valor para uno o más receptores y existe necesidad de verificar suficientemente si ese valor ocurre y cómo se distribuye o captura.
Estructura mínima:
VALUE RECIPIENT + VALUE INTENT + EXPECTED OUTCOME + EVIDENCE + OBSERVED OUTCOME + ATTRIBUTION
Ejemplo:
No:
“el ecommerce creció 20 %.”
Sí:
“La nueva experiencia de compra buscaba reducir abandono y aumentar conveniencia para clientes móviles; necesitamos saber si produjo ese resultado, qué parte del incremento comercial puede razonablemente atribuirse y si el valor capturado compensa el costo adicional.”
Ahora existe un VCC.
# 3. Valor ≠ ingreso
Revenue puede ser una forma de:
value capture.
Pero no demuestra por sí mismo:
value creation.
Una empresa podría aumentar ingresos mediante:
- aumento de precio;
- mayor volumen;
- descuento agresivo;
- concentración;
- adquisición costosa;
- deterioro de margen.
### P-CM06-CORE-01
Ingreso es una medida económica relevante, pero no constituye por sí solo evidencia suficiente de creación de valor.
# 4. Valor ≠ resultado positivo cualquiera
Un indicador puede mejorar y no ser material.
Ejemplo:
visitas web +50 %.
Si no cambia:
- adquisición pertinente;
- conversión;
- experiencia;
- valor económico;
su relevancia puede ser baja.
### P-CM06-01
Una variación positiva en una métrica no constituye creación de valor hasta establecer su relación con un resultado material para algún receptor relevante.
# 5. Aplicabilidad
CM-06 no exige monetizar todo.
Puede existir valor:
- funcional;
- económico;
- temporal;
- experiencial;
- de riesgo;
- de conveniencia;
- de capacidad;
- de aprendizaje.
Pero la profundidad aumenta cuando el resultado:
- determina inversión;
- condiciona rentabilidad;
- afecta continuidad;
- justifica escala;
- requiere priorización;
- genera trade-offs relevantes.
# 6. Materialidad
Drivers:
- impacto para cliente;
- magnitud económica;
- recurrencia;
- inversión;
- irreversibilidad;
- dependencia;
- duración;
- escalabilidad;
- concentración;
- riesgo;
- efecto sobre otras partes interesadas.
No construimos un score universal.
# 7. Fronteras
## CM-06 vs CM-02
CM-02:
qué valor prometemos.
CM-06:
qué valor realmente se genera y captura.
Por tanto:
VALUE PROMISE ≠ VALUE REALIZATION.
# 8. CM-06 vs CM-03
CM-03 puede medir:
- conversión;
- renovación;
- expansión.
CM-06 pregunta:
¿qué valor producen realmente esas relaciones y cuánto logra capturar el negocio?
Una tasa de renovación alta no demuestra:
relación económicamente valiosa.
# 9. CM-06 vs CM-05
CM-05 puede demostrar:
experiencia positiva.
CM-06 puede encontrar:
costo de servicio desproporcionado.
Ambas conclusiones pueden coexistir.
# 10. CM-06 vs DT-04
DT-04:
producir información útil para decisiones.
CM-06:
define y gestiona específicamente la información de creación y captura de valor.
CM-06 consume la capacidad analítica de DT-04.
# 11. CM-06 vs DG-04
DG-04:
seguimiento de iniciativas y resultados.
CM-06:
arquitectura específica de resultados de valor cliente-negocio.
Un proyecto puede cerrarse “en tiempo y presupuesto” y:
no crear valor.
# 12. Value Recipient
No existe valor en abstracto.
Definimos:
### VALUE RECIPIENT — VR
Parte que recibe o experimenta un resultado material.
Puede ser:
- cliente;
- usuario;
- comprador;
- negocio;
- empleado;
- partner;
- otro actor cuando sea material.
CM-06 se concentra en:
customer + business value
pero puede registrar terceros cuando sean necesarios para comprender el caso.
### P-CM06-02
Todo resultado de valor debe poder asociarse suficientemente con un receptor relevante.
# 13. Customer Value
Definimos:
### CUSTOMER VALUE
beneficio o resultado material experimentado por el cliente en relación con los costos, esfuerzos, riesgos o alternativas relevantes asociados a obtenerlo.
Esto no implica una fórmula universal.
Puede manifestarse como:
- ahorro;
- ingreso;
- tiempo;
- conveniencia;
- calidad;
- reducción de riesgo;
- resultado funcional;
- menor esfuerzo;
- capacidad nueva;
- experiencia.
# 14. Business Value
Definimos:
### BUSINESS VALUE
resultado material que mejora suficientemente la capacidad económica, estratégica, operativa o de continuidad de la organización.
Puede incluir:
- margen;
- cash flow;
- productividad;
- crecimiento;
- retención rentable;
- capacidad;
- reducción de riesgo;
- aprendizaje estratégico.
No reducimos business value a:
revenue.
# 15. Customer Value ≠ Business Value
Puede existir:
alto valor para cliente
y:
bajo valor para negocio.
Ejemplo:
servicio extraordinariamente personalizado y barato.
También puede existir:
alto valor capturado a corto plazo
pero:
bajo valor para cliente.
Eso puede deteriorar relación futura.
### P-CM06-03
La creación sostenible de valor requiere mantener visibles los resultados para cliente y negocio sin asumir que necesariamente se mueven en la misma dirección.
# 16. Value Created
Definimos:
### VALUE CREATED
resultado material favorable efectivamente producido para un receptor respecto de una condición de referencia suficientemente relevante.
Necesitamos:
- outcome;
- receptor;
- comparación;
- evidencia.
# 17. Value Captured
Definimos:
### VALUE CAPTURED
porción del valor económico o estratégico que la organización logra retener mediante ingresos, margen, ahorro, capacidad, información u otro resultado material.
No es idéntico:
al valor total creado.
# 18. Value Delivered
Para mantener coherencia con CM-02:
### DELIVERED VALUE
Aquello que la oferta efectivamente proporciona.
### REALIZED VALUE
Aquello que produce un resultado para el receptor.
### CAPTURED VALUE
Aquello que el negocio obtiene a cambio.
Cadena:
DELIVERED → REALIZED → CAPTURED
sin asumir relación 1:1.
# 19. Value destruction
Necesitamos también un estado negativo.
### VALUE DESTROYED
resultado en que una actividad genera costos, fricción, pérdida, riesgo o consecuencias materiales superiores al valor suficiente producido para algún receptor relevante.
No significa necesariamente:
pérdida financiera inmediata.
Ejemplo:
crecer ventas destruyendo capacidad de servicio.
### CAND-MOTOR-CM06-01
El Motor debe poder representar value created, neutral value y value destroyed, no únicamente resultados positivos.
# 20. Output ≠ Outcome ≠ Impact
Esta separación es central.
### OUTPUT
Lo producido directamente.
Ejemplo:
500 capacitaciones.
### OUTCOME
Cambio observado derivado en el sistema/receptor.
vendedores utilizan mejor la herramienta.
### IMPACT
Consecuencia material más amplia o duradera.
menor tiempo de ciclo y mejor conversión.
No siempre necesitamos llegar a impacto.
### P-CM06-04
El nivel de resultado utilizado debe corresponder con la decisión y la fuerza de evidencia disponible.
# 21. Activity ≠ Output
También preservamos:
realizar una actividad
no significa:
producir el output.
Y output:
no significa outcome.
Cadena:
ACTIVITY → OUTPUT → OUTCOME → IMPACT
pero no la tratamos como causal automática.
# 22. Value intent
Antes de medir debemos saber:
qué valor pretendíamos crear.
Definimos:
### VALUE INTENT
resultado material esperado para un receptor que justifica una actividad, oferta o inversión.
Puede venir de:
- CM-02;
- iniciativa;
- customer need;
- business objective.
# 23. Value hypothesis
Un VCC puede comenzar como:
VALUE HYPOTHESIS
“Si hacemos X, esperamos generar Y para Z.”
Necesitamos conservar:
hypothesis ≠ observed outcome.
# 24. Baseline
Para afirmar:
“creamos valor”
frecuentemente necesitamos referencia.
Puede ser:
- before;
- target;
- alternative;
- control;
- historical;
- expected trajectory;
- benchmark relevante.
### P-CM06-05
Sin referencia suficiente puede ser posible describir un resultado, pero no necesariamente determinar cuánto valor adicional se creó.
# 25. Counterfactual
La atribución fuerte requeriría preguntar:
¿qué habría ocurrido sin la intervención?
No siempre podemos saberlo.
Por tanto:
no exigimos experimentos causales para toda pyme.
Pero mantenemos explícita la incertidumbre.
# 26. Metrics
Una métrica de valor debe responder:
VALUE QUESTION + RECIPIENT + OUTCOME
Ejemplo:
“tiempo de entrega” puede ser una métrica.
Pero su valor depende de:
qué resultado genera para cliente/negocio.
### P-CM06-06
Medir una variable no demuestra que la variable represente valor.
# 27. Leading vs lagging
Podemos utilizar:
### LEADING SIGNAL
Señal anticipatoria.
### OUTCOME METRIC
Resultado observado.
Pero:
leading ≠ outcome.
Ejemplo:
adopción puede anticipar productividad.
No demuestra:
productividad.
# 28. Financial vs non-financial
No creamos una jerarquía.
Puede ser necesario medir:
- ahorro;
- margen;
- NPS;
- tiempo;
- defectos;
- riesgo;
- capacidad.
La métrica debe responder al VCC.
# 29. Unit economics
En algunos modelos es esencial.
Puede incluir:
- revenue/customer;
- gross margin;
- CAC;
- cost-to-serve;
- contribution;
- lifetime economics.
Pero Pymapa no exigirá:
LTV/CAC universalmente.
### P-CM06-07
Las métricas económicas deben activarse cuando sean materiales para comprender captura y sostenibilidad del valor, no como plantilla universal.
# 30. Revenue growth ≠ profitable growth
Regla estructural:
### P-CM06-08
El crecimiento debe evaluarse junto con los economics materiales suficientes para evitar confundir expansión de volumen con creación sostenible de valor.
# 31. Attribution
Reutilizamos:
ATTR-0:3
como servicio transversal.
Podemos interpretar:
### ATTR-0
Asociación desconocida.
### ATTR-1
Asociación plausible.
### ATTR-2
Contribución razonablemente sustentada.
### ATTR-3
Atribución fuerte dentro de condiciones definidas.
No toda decisión exige ATTR-3.
# 32. Attribution ≠ contribution
Muchas intervenciones:
contribuyen
pero no son causa única.
### P-CM06-09
Cuando múltiples factores intervienen, Pymapa debe preferir lenguaje de contribución salvo que exista evidencia suficiente para atribución causal más fuerte.
# 33. Correlation
Si después de lanzar nueva campaña:
ventas aumentan.
Eso no prueba:
campaña causó el aumento.
Puede haber:
- temporada;
- precio;
- mercado;
- otro canal;
- tendencia.
DT-04 ya nos dio guardrails causales.
CM-06 los reutiliza.
# 34. Time horizon
El valor puede aparecer en distintos horizontes.
Ejemplo:
automatización puede:
- aumentar costo inicialmente;
- generar ahorro después.
Definimos:
### VALUE HORIZON
periodo material dentro del cual debe observarse el resultado esperado.
### P-CM06-10
La evaluación de valor debe utilizar un horizonte compatible con el mecanismo mediante el cual se espera que el resultado ocurra.
# 35. Trade-offs
Valor puede mejorar para un actor y deteriorarse para otro.
Ejemplo:
reducir soporte humano:
- baja costo;
- aumenta customer effort.
Definimos:
### VALUE TRADE-OFF
situación en la que una decisión mejora un resultado de valor y deteriora otro suficientemente material.
No intentamos eliminar trade-offs.
Necesitamos:
hacerlos visibles.
# 36. Local optimization
Una unidad puede mejorar su KPI y:
deteriorar valor global.
Ejemplo:
ventas ofrece descuentos para aumentar conversión.
Resultado:
revenue alto, margen bajo.
### P-CM06-11
La optimización de una métrica local no debe tratarse como creación de valor global sin observar consecuencias materiales relacionadas.
# 37. Value leakage
Introducimos:
### VALUE LEAKAGE
pérdida material entre valor potencialmente creado y valor efectivamente realizado o capturado.
Puede aparecer por:
- descuentos;
- mala adopción;
- servicio caro;
- errores;
- churn;
- fricción;
- baja utilización;
- mala monetización.
Será útil como finding.
# 38. Value sustainability
No basta producir valor una vez.
Puede ser importante:
poder sostenerlo sin destruir otros resultados.
Definimos:
### SUSTAINABLE VALUE CONDITION
estado en que la generación/captura de valor puede mantenerse razonablemente dentro de restricciones económicas, operativas y relacionales relevantes.
No estamos haciendo aquí sustainability ESG universal.
# 39. ISO / grounding
Para grounding de esta capacidad, ISO 10014:2021 sigue publicada y proporciona orientación para lograr beneficios financieros y económicos mediante seguimiento de métricas clave y acciones de mejora; está dirigida a organizaciones de cualquier tamaño o modelo. Actualmente figura en revisión, por lo que conviene mantener un trigger documental. ISO
Además, acaba de publicarse ISO 9001:2026, que reemplaza ISO 9001:2015. La nueva edición enfatiza la entrega consistente de valor, resultados beneficiosos, mejora y toma de decisiones, manteniendo aplicabilidad a organizaciones de cualquier tamaño. ISO
Esto no convierte CM-06 en gestión de calidad ISO. Lo utilizamos como grounding externo para:
- resultados;
- mejora;
- beneficios;
- métricas;
- toma de decisiones;
- valor sostenible.
La OECD sigue reforzando, en contexto pyme, que la digitalización debe entenderse por el valor que genera para competitividad y operaciones, no únicamente por adopción de herramientas. OECD

# 41. Information Needs

¿Qué valor esperamos crear, para quién, cómo sabremos que ocurrió, qué parte puede atribuirse razonablemente a nuestras acciones, cuánto valor logra capturar el negocio y qué decisión debería cambiar si la evidencia no confirma la hipótesis?
# 42. Captura P1
Preguntas naturales:
“¿Cómo saben que lo que están haciendo realmente genera valor para el cliente?”

“¿Hay clientes o líneas que venden mucho pero dejan poco valor?”
“¿Qué seguirían haciendo menos o dejarían de hacer si vieran que no genera suficiente valor?”

# 47. Evidence proportionality
Un cambio pequeño y reversible puede usar:
evidencia ligera.
Una inversión grande puede requerir:
mayor profundidad.
### EVID-CM06-01
La fuerza de evidencia requerida aumenta con magnitud de inversión, irreversibilidad, incertidumbre y consecuencia de una conclusión equivocada sobre valor.
# 48. Suficiencia
### SUFF-CM06-01
CM-06 alcanza suficiencia cuando los casos materiales de valor tienen receptores y resultados suficientemente definidos, evidencia proporcional sobre outcomes, medición y atribución compatibles con la decisión, y capacidad de ajustar o detener inversiones, ofertas o relaciones cuando el valor creado o capturado resulta insuficiente.
No exige:
conocer exactamente toda causalidad.
# 49. Confianza
Distinguimos:
### OUTCOME CONFIDENCE
¿El resultado ocurrió?
### CUSTOMER VALUE CONFIDENCE
¿Representa valor para cliente?
### BUSINESS VALUE CONFIDENCE
¿Representa valor para negocio?
### ATTRIBUTION CONFIDENCE
¿En qué grado nuestras acciones contribuyeron?
### VALUE CAPTURE CONFIDENCE
¿En qué grado el negocio captura el valor?
### SUSTAINABILITY CONFIDENCE
¿Puede mantenerse?
### CAND-MOTOR-CM06-02
La confianza en un outcome observado no debe transferirse automáticamente a confianza en valor, atribución o sostenibilidad.

# 52. Guardrails
- No confundir revenue con valor.
- No confundir growth con profitable growth.
- No confundir output con outcome.
- No confundir outcome con impact.
- No asumir métrica positiva = valor.
- No asumir customer satisfaction = customer value.
- No asumir customer value = business value.
- No asumir business value = cash inmediato.
- No exigir monetizar todo.
- No exigir ROI para toda intervención.
- No usar ROI sin hipótesis/periodo suficientes.
- No exigir LTV/CAC universalmente.
- No asumir alta retención = alto value.
- No asumir alta conversión = alto value.
- No asumir alta utilización = value.
- No asumir ahorro = value si desplaza costos relevantes.
- No ignorar cost-to-serve.

## El finding debe preservar el Value Creation Case
Evitemos:
“La iniciativa no genera valor.”
Preferimos:
“La automatización de elaboración de propuestas redujo el tiempo medio de preparación, pero el ahorro neto sigue siendo incierto porque aumentaron las revisiones manuales y no existe todavía evidencia suficiente de impacto sobre conversión o capacidad comercial.”
Ahora tenemos:
VALUE INTENT + OBSERVED OUTCOME + OFFSETTING EFFECT + ATTRIBUTION/ECONOMIC UNCERTAINTY
### FIND-CM06-01
Todo finding CM-06 debe conservar receptor, resultado esperado, evidencia observada, horizonte y nivel de atribución suficiente para interpretar la conclusión.

# Resultado positivo ≠ net positive value
Una intervención puede producir:

y simultáneamente:
+30 % errores.
No queremos que Pymapa “promedie” ambos sin comprender materialidad.
### CAND-MOTOR-CM06-15

# Vocabulario de decisión

### CLARIFY_VALUE

### DEFINE_MEASURE

### ESTABLISH_BASELINE
Introducir referencia necesaria.
### ACQUIRE_EVIDENCE
Obtener evidencia adicional con VoI suficiente.
### QUALIFY_ATTRIBUTION
Reducir fuerza de una atribución o hacer explícita incertidumbre.

Cerrar brecha entre valor creado y capturado.
### REDUCE_LEAKAGE
Tratar pérdidas de valor.
### MITIGATE_TRADEOFF

### STOP_DESTRUCTION
Interrumpir una actividad que destruye valor.
### MAINTAIN
Mantener configuración actual.
### ADJUST
Modificar intervención, oferta, relación o asignación.

Escalar cuando evidencia y sostenibilidad lo justifican.
### REDUCE
Disminuir alcance/inversión cuando el valor marginal cae.
### STOP
Detener cuando el valor observado es insuficiente.
### NO_ACTION
No intervenir cuando la condición ya es suficiente.

# Expand no es premio
Pymapa no debe inferir:
“si funciona, escalar”.
Antes necesitamos comprobar:
- marginal value;
- capacity;
- economics;
- trade-offs;
- reproducibility.
### P-CM06-12
La evidencia de valor en un alcance limitado no debe generalizarse automáticamente a una escala mayor.

# Stop también puede ser buen gobierno
Una iniciativa puede haber sido razonable y luego dejar de crear valor.
Detenerla no significa:
“fracasó el proceso”.
Puede significar:
el sistema de gestión está funcionando.
### P-CM06-13
La decisión de detener una iniciativa por evidencia suficiente de bajo valor puede constituir una manifestación positiva de CM-06.

# Marginal Value
Introducimos un concepto especialmente útil:
### MARGINAL VALUE
Valor adicional esperado u observado al aumentar una unidad relevante de inversión, alcance o esfuerzo.
No siempre puede cuantificarse.
Pero evita:
“algo crea valor, por tanto más siempre es mejor”.
### P-CM06-14
Value creation total y marginal value deben poder divergir; una iniciativa valiosa puede haber alcanzado un punto donde expandirla deja de ser conveniente.

# Minimum Sufficient Value Measurement
Formalizamos:
### INT-CM06-01
Debe utilizarse el conjunto mínimo de resultados, métricas, comparadores y evidencia capaz de soportar suficientemente la decisión material sobre creación y captura de valor.
No buscamos:
tableros gigantes.
Buscamos:
decisión informada.

# Minimum Sufficient Attribution
### INT-CM06-02
La fuerza de atribución requerida debe limitarse al nivel mínimo suficiente para la decisión; no debe exigirse demostración causal más sofisticada cuando una estimación de contribución suficientemente robusta permite decidir responsablemente.
Esto mantiene CM-06 usable para pyme.
